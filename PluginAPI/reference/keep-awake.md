# Keep Awake and Host activities (Plugin API Level 2)

The Host owns effects after a gesture starts them; the Plugin helper ends
normally and closing or hiding its Plugin View does not stop them. New IDs
and the `keep_awake` Capability are additive Level 2 members (#84).

| ID | Offered as | Input | Result | Capability |
| --- | --- | --- | --- | --- |
| `system.keepAwake` | command, request, page action | `{mode: "manual"}`, `{mode: "duration", seconds}`, or `{mode: "app_alive", target}` | null | `keep_awake`; App-alive also `read_frontmost_app` |
| `activities.list` | call | none | active own activities | none |
| `activities.stop` | request, page action | `{id}` | null | none |

```js
return spinnet.ui.request(spinnet.system.keepAwake.operation(
  {mode: "duration", seconds: 3600}, {notify: true}));
// On a subsequent invocation:
const held = spinnet.activities.list();
return spinnet.ui.request(spinnet.activities.stop.operation({id: held[0].id}));
```

## Scope and limitations

Each effect owns **both** PreventUserIdleSystemSleep and
PreventUserIdleDisplaySleep assertions. It keeps the Mac and display awake
while idle, including on battery, subject to macOS power policy. Explicit
Sleep, closing the lid, critical battery and other forced/system sleep still
apply. It promises neither uninterrupted execution nor prevention of every
kind of sleep. Plugins cannot choose assertion types or hold another
resource, run a subprocess, or define menu-bar content.

Both assertions must be acquired before the effect starts; if either fails,
any already-acquired assertion is released and the request fails. A failed
creation creates no activity. Every effect has a Host-generated name from
the installed Plugin name, mode status and a Stop control in the Host Status
Item, which also discloses the scope and limitations.

## Lifetime and authority

- Manual lasts until stopped. Duration has an integer `seconds` from 1 to
  86400; a Host-owned monotonic timer expires it, regardless of helper/view
  lifetime. App-alive binds an opaque App Target already given to **this**
  Plugin by `apps.frontmost`, and lasts until that exact running App exits.
  A later App reusing its process ID or relaunching never inherits it. Losing
  an App Target merely because its 16-target bound evicts it does not end an
  already bound effect; it holds the resolved identity independently.
- `keep_awake` is an explicit grant, separate from reading App identity;
  App-alive checks `read_frontmost_app` again at start. A Level 1 Plugin may
  not declare it. It needs no `capability_scopes` entry or System Permission.
- Explicit Stop, expiry, bound App exit, any Plugin disable, update,
  replacement/removal or Capability revocation, and Host exit release both
  assertions. **Update means every replacement/reload**, even if a package
  reuses its manifest version; effects are never migrated to the new copy.
- A pending start keeps the owner registration and authority lifetime from
  when the Host accepted it. Replacement with the same manifest, disabling
  then enabling, or revoking then granting again cannot make that old start
  current: it acquires no assertions, and only a new user call may start a
  new effect.
- Closing/hiding the Plugin View and helper retirement have no effect on
  the ongoing resource. Pending requests still obey Requested Host Operation
  cancellation; an effect that has started has its own lifetime.
- Normal exit releases all effects before ending the Host. macOS releases
  process-owned assertions on crash/logout. Relaunch starts empty, with no
  journal, recovery or automatic restart.

Each start creates a separate effect; there is no implicit toggle or
replacement. At most 8 activities per Plugin and 64 Host-wide are active.
If either limit is reached the new start fails and releases its assertions.

## Activities

`activities.list()` returns a bounded array of `{id, kind, name, status,
expires_at}`. `kind` is `keep_awake`, `id` is `activity_` plus 32 lowercase
hexadecimal digits, `expires_at` is Unix seconds for a duration or null.
Name/status are generated by the Host; no process ID, App Target, grant or
another Plugin's activity is exposed. App-bound status names only the App
this Plugin already identified. Order is not a promise.

`activities.stop` succeeds with null for a missing, ended or foreign ID and
releases nothing owned by another Plugin. The Host's own Stop can stop any
owner. Stopping an already stopped activity is a no-op. These controls are
resource ownership machinery, separate from view-visible sources and future
mutating Tasks: Task cancellation/rollback rules must be defined by their
own adapter, rather than copied from keep-awake effects.

## Test kit and fixtures

`RecordedKeepAwake` supplies the Host's real effect registry, recorded time,
recorded power and `RecordedApps`. `advance(by:)` expires timers;
`power.failing` can refuse either assertion, and `power.held` / `power.count`
show their lifetime. `effects.invalidate(pluginID)` stands for disable,
update/removal or revocation; `effects.shutdown()` stands for Host exit.
Pass it as `keepAwake:` to `RecordedHostServices` and
`RecordedHostOperations`, then run an external package in the real helper.
It substitutes OS/time boundaries; it does not prove actual sleep behaviour.
Published [fixtures](../fixtures/keep-awake/index.json) match the
[namespaces schema](../schemas/namespaces.schema.json).
